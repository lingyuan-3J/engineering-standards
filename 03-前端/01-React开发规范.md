# React 开发规范

适用于 React、TypeScript。Next.js 特有约定仅用于采用该框架的项目；依赖版本、组件库和接口地址由项目决定。

## 1 页面组织

Next.js App Router 的实际页面直接写在对应 `app/.../page.tsx`，页面专属 CSS Module 同目录。禁止 `page.tsx` 仅转发另一份完整页面，也不另建领域 `pages/` 镜像路由。

领域目录维护接口、类型和专用组件；有独立职责时提取表单或局部组件，不为拆分搬走完整页面。其他路由框架同样按真实入口组织。

## 2 组件职责

公共展示组件通过 props 接收数据、配置和状态，通过回调通知操作，不导入某领域业务 API。业务页面负责请求及提交编排。业务专用组件先留在本领域，稳定复用后再提升到公共目录。

表单类型与接口 DTO 分开，显式转换请求字段。列表区分加载、失败、空结果；筛选变化回到第一页，分页状态只有一个维护来源。

## 3 状态管理

会话等跨页面状态按需要集中维护，筛选、编辑草稿及弹窗采用局部状态。Effect、订阅和异步请求有对应清理；旧请求不能覆盖新条件或新账户，写操作不因网络错误自动重试。

## 4 样式组织

组件和页面样式遵循 [通用编码规范](../01-通用编码规范.md#6-样式归属)。React 项目默认使用独立 CSS Modules，文件随所属组件或页面维护；既有其他方案由项目约定。

## 5 运行边界

Next.js 服务端及客户端边界明确。浏览器存储只在客户端初始化后访问，服务端不根据浏览器缓存猜测会话，不把私人资料放入公共缓存。后端已有业务接口时，不在前端另建同名保存流程。

## 6 请求处理

请求和上传复用本项目基础层，JSON 与 FormData 分别设置请求体，上传不手动拼 multipart boundary。401、网络故障和业务错误分别处理；并发失效会话统一清理，旧请求不能清除新凭证。

凭证只发送至明确的本项目服务端。页面路由前缀与 API 前缀分别维护，公开环境变量不包含服务端秘密。

## 7 功能图标

新项目默认采用 Lucide，通过 `lucide-react` 显式导入所需图标。已有图标体系按项目约定保持一致，不用字符或 Emoji 代替功能图标，不封装只转发 props 的图标空壳，不动态加载整套图标。

颜色继承 `currentColor`，图标和文字以布局间距对齐。已有文字的装饰图标使用 `aria-hidden`，纯图标按钮提供 `aria-label`，展开控件提供明确的展开状态。

## 8 工程验证

遵循项目已锁定版本和格式配置，修改前查看对应依赖的本地文档。按改动运行格式、类型、lint 和构建检查，不复制参考工程的全部依赖和运行配置。
